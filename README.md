# 关于这个开源项目

## 前言

项目内容：25年电赛E题矩形目标靶识别代码，以及对26年电赛控制题的想法

因为最终版的报告和代码我找不到了，这里放的是比赛结束前一天的版本

视觉模块用的是K230，单片机是STM32F103C8T6和MSPM0G3507，另外我们还准备了几个外部按键

## 这里有哪些资料

**1.** report文件夹是电赛报告模板，细节详见report文件夹内的README.md


**2.** 2025E_ColorBlockTracking.py是我在2025年电赛E题最开始用的方案。核心思路是：

- 直接通过LAB色块追踪找到目标靶的黑色外边框。如果确定是目标靶，应该满足下面条件：

    1. 色块的面积适中，即宽度和高度不能太小或太大

    2. 色块的长宽比适中，太小或太大可能是测试场地里面的狭长黑色缝隙

    3. 黑色边框内部主要是白色，即R+G+B > 300，这是根据靶子的实际情况得到的，其实有没有这个逻辑好像结果差不多？

- 通过阻塞式按键进行脱机阈值调整，因为测评场地和实验室场地有区别，测评又不能带电脑，用外部按键现场调参数

- 通过打包函数把中心坐标变成所需格式，用串口通信发给STM32，这是参考了一个开源代码


**3.** 2025E_Rectangle_Detection.py是我在2025年电赛E题最后用的方案。核心思路是：

- 分成阈值调整和目标追踪两个阶段，阈值调整阶段即通过阻塞式按键进行脱机阈值调整

- 通过灰度阈值进行二值化，然后进行矩形检测。如果确定是目标靶，其长宽比与面积应该适中

- 通过打包函数把中心坐标变成所需格式，用串口通信发给STM32，这是参考了一个开源代码


**4.** take_photo.py是用于K230视觉模块拍照记录。如果你实在做不出来需要YOLO兜底，这里需要采集目标的图像数据，你肯定不能用手机一张一张地拍。这个代码的作用是，按下K230的按键，拍照并保存到给定文件夹



## 关于我对25/26年电赛的看法

- 25年E题视觉：检测一个矩形目标靶，定位靶心并用激光模块打靶。那时候有三个思路，最后煮波用的是第二个：①用LAB色块追踪，直接定位靶心。优点是没有拍到完整目标靶的情况下也能检测到目标，缺点是靶子可能有一点点倾斜的情况下中心定位精度相对没那么高；②用LAB阈值二值化，矩形透射变换定位靶心。优点是中心定位精度很高，缺点是必须拍到完整的矩形靶子；③用YOLO直接定位中心。优点是抗干扰能力强，不需要调一堆阈值，缺点是帧率远低于前两种方法，中心点定位也不够准确
	
- 26年电赛控制题视觉：听说是钢珠识别与计数。煮波的想法主要有两个：①直接上YOLO，优点是受钢珠表面反光的影响小，缺点是定位精度相对没那么高，实时性也会差一点；②用LAB阈值做二值化，然后做霍夫圆变换定位中心，优点是速度快而且不用采集数据集，缺点是容易受到外部因素干扰
	
- 如果26年真的是做钢珠检测的话，感觉主要问题有：①如何解决检测过程中的目标丢失问题，在通信过程中，是直接发送（0，0），还是发送上一次坐标，还是用卡尔曼滤波；②如何解决钢珠影子导致结果的中心点偏移问题，通过调整拍摄角度与光源位置能否改善这一问题；③两个钢珠粘连时如何确定这个色块表示两个钢珠并分别得到钢珠中心坐标，分水岭算法或者腐蚀膨胀是否有效；④如何解决钢珠反光导致LAB色块追踪无法获得完整色块的问题，如果无法解决，能不能直接加强光然后根据反光点的数量进行计数


## 做视觉有哪些要注意的地方

电赛视觉部分需要注意下面几点：
- 脱机阈值调整。如果用LAB色块追踪，代码中会设置很多参数比如LAB的最大最小值。因为比赛现场跟学校实验室的光照不一样，这些参数会发生变换，你又不能带电脑到现场改参数，所以要为视觉模块增加几个外部按键，通过GPIO口在现场测评前修改参数，如果有钱的话也可以直接用触摸屏搞个调试软件

- 平衡实时性与精度。如果比赛对实时性要求比较高，而且要检测的东西属于规则物体+固定颜色，比如去年E题的打靶问题，那传统视觉就能解决；如果对实时性要求低但是对精度要求高，那才可以上YOLO，比如送药小车的数字识别

- 供电问题。如果一个端口同时给视觉模块，电机之类的乱七八糟的东西供电容易产生电压不稳，视觉模块可能突然黑屏，碰到这种情况需要考虑给视觉模块单独供电。像我代码里面那样用阻塞式按键好像也可能是产生这个问题的原因，我没想到别的方法

- 用K230可以学一下嘉楠社区进阶教程里面的cv_lite，帧率会比常规教程里面那些方法高很多，去年煮波偷懒了没学（）

- OpenMV的性能感觉不如K230， Maxicam之类的。另外最好准备一下备用的单片机，视觉模块和其他材料，防止比赛的时候出现意外烧掉
